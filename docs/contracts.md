# Shared contracts and handoff

`src/contracts.ts` exports the shared types. These are data contracts, not engine implementations. Coordinate changes before dependent lanes diverge.

- Theory consumes `SpelledPitchClass`, `ScaleFamily`, `ModeDegree`, `ChordQuality` and practice inputs; it owns canonical definitions, spelling, derivation, symbols and `PitchCompatibleCandidate` results. Initially the quality selector offers `maj7`, `m7`, `7`, `m7b5`, `m(maj7)`, `maj7#5`, and `dim7`: the literal seventh qualities in the supported families. Candidates contain every selected chord pitch class in the mode. An empty list is valid; label matches pitch-compatible, not recommendations. The candidate's chord is the selected chord, not necessarily the mode's literal chord.
- A spelled pitch class carries sounding identity C=0 through B=11; a `Pitch` additionally carries written octave and MIDI sounding identity. Producers must keep these consistent, including enharmonics and octave-crossing accidentals. Audio consumes `PlaybackVoicing` actual pitches, never chord symbols. `PlaybackStatus` distinguishes stopped, pending startup, playing and rejected/error. Audio owns gesture-triggered start, explicit stop and dispose, and must prevent a pending start from reviving sound after stop/dispose. Changes while stopped do not start sound.
- Guided practice distinguishes parent tonic/family from selected modal tonic/degree. Switching derivative mode preserves `positionId`; visualization consumes spelled mode notes and `Fingering` ordered events, not harmonic logic. Strings use guitar numbering (1 highest); source and review state are explicit. Unreviewed or rejected data must not be represented as validated CAGED.
- UI owns presentation components, not the app entry. Components receive typed values and controlled inputs with callbacks for user changes, play and stop; do not duplicate theory or audio logic. Native controls and accessible labels are the default. Integration owns final composition and `src/main.tsx`; this scaffold's entry is temporary. Theory, audio and UI should expose their own named module exports from their respective directories and coordinate concrete APIs at integration rather than edit shared entry/config independently.

Fixtures in `src/contracts.test.ts` demonstrate consumer imports, D melodic minor to F Lydian augmented, a retained position, self-guided selection, voicing and pending/error status. They are contract examples, not theory validation.
