# Research: reusable CAGED scale positions for Practice Pads

**Session:** 2026-10-29, from inherited session metadata, not an independently read system clock. This is bounded source research, not a complete package census; no app installs, implementation or runtime compatibility tests were performed. The existing prototype pitch map is not a validated fingering source.

## Summary and verdict

**No complete, clearly reusable source was verified** for five teacher-acceptable CAGED scale fingerings, including open positions, consistent ordered exercises and all three parent families. Two genuinely substantive leads deserve follow-up: fretboard.js contains five explicit major-derived CAGED point templates, while Guitar Positions generates fingered, ascending box patterns for all three interval families. Neither has demonstrated the full requirement: fretboard.js does not encode the two minor-family shapes or fingers; Guitar Positions calls its generated boxes CAGED-*like*, and its README's MIT statement conflicts with the absence of a LICENSE file and unresolved provenance.

**Recommendation: defer adoption** until a musician reviews actual outputs and rights are clarified. Seek licensed teacher-provided position/exercise data covering all three families, or agree on a smaller reviewed launch scope; do not substitute a custom engine, invented dataset, generic pitch map, or arbitrary fret windows. This is an assessment of sources investigated, not a claim none exists anywhere.

## Findings and direct evidence

### 1. Genuine CAGED data in fretboard.js is narrower than its scale API

**Direct evidence, high confidence:** [systems.ts](https://github.com/moonwave99/fretboard.js/blob/master/src/fretboardSystem/systems/systems.ts) has `CAGED_ORDER = 'GEDCA'` and five six-string arrays of degree markers and dashes. For example, one is `['71-2','-5-6','2-34','6-71','34-5','71-2']`; code translates their offsets into string/fret coordinates, uses root chroma to transpose, and adjusts the mode by the major-mode offset. This is **real specified point-shape geometry**, not simply a rectangular filter. The [documentation](https://moonwave99.github.io/fretboard.js/documentation-music-tools.html) explicitly demonstrates D major C shape. Its default tuning is standard; see [constants](https://github.com/moonwave99/fretboard.js/blob/master/src/constants.ts) and docs. Source uses six string-indexed rows; verify convention against renderer before adapter use.

**Direct evidence plus interpretation, high confidence:** [FretboardSystem.ts](https://github.com/moonwave99/fretboard.js/blob/master/src/fretboardSystem/FretboardSystem.ts) first gets all scale notes from Tonal, then marks intersections with the selected template as `inBox`. [systems.ts](https://github.com/moonwave99/fretboard.js/blob/master/src/fretboardSystem/systems/systems.ts) obtains mode numbers from `@tonaljs/mode`, and contains no separate jazz melodic or harmonic minor CAGED template. A scale name recognized by Tonal is therefore **not evidence** that its correct minor-family box is encoded. The API returns positions and emphasis, not a reviewed ordered exercise or finger assignment. Open/nut and octave adjustment are coded, but correctness of all keys and open fingerings remains untested. Major shape suitability needs human review.

Manifest identifies version 0.2.12, browser/ES module entry points and runtime dependencies on `@tonaljs/{interval,mode,note,scale}`, `d3-selection`, `change-case`, and `throttle-debounce`; a selected distribution needs a notice and transitive audit. This indicates a possible static-browser integration route, **not a tested React/Vite compatibility guarantee**. Repository tree inspected at commit `d0afe2d7bc8e8beb397d3269d78567dcf3546523`; package version is a branch observation, not a latest-release claim. Dataset origin and separate reuse terms were not found.

### 2. Guitar Positions is a stronger minor-family lead, but not proven named CAGED

**Direct evidence, high confidence:** [theory.js](https://github.com/hybridpicker/fretboard-position-finder/blob/master/static/studio/js/theory.js) has standard tuning MIDI `[40,45,50,55,59,64]` lowest string first, classic string numbers `[6,5,4,3,2,1]`, major intervals `[0,2,4,5,7,9,11]`, ascending jazz melodic minor `[0,2,3,5,7,9,11]`, and harmonic minor `[0,2,3,5,7,8,11]`. `scalePositions` builds positions using intervals and tonic, folds start frets below 12, and regular-tuning `buildBox` constructs ascending-pitch notes with fret/stretch constraints; `fingerBox` heuristically assigns fingers, marks stretches and assigns 0 to open strings. It removes similar positions, sorts by neck location and numbers them. Source distinguishes three-notes-per-string from its box system, and uses a raw fret window for non-regular tunings.

**Interpretation, medium confidence:** This is more than a generic all-notes map for standard tuning: it selects a pitch-ordered path with finger annotations. But source calls it “one finger per fret, CAGED-style”; it does not associate the boxes with the five named chord templates. Five results for every tonic/family are claimed by the [README](https://github.com/hybridpicker/fretboard-position-finder), not established by exhaustive inspection or execution. Its per-string order should not be assumed to be an approved root-to-root exercise or descending tab; map/review the actual returned sequence and duplicate pitches. Preserve the parent key/position rather than recomputing from selected mode, especially D melodic minor → F Lydian augmented.

The [README](https://github.com/hybridpicker/fretboard-position-finder) says MIT while GitHub's license metadata is null and the inspected tree lacks a standalone license. An MIT statement is meaningful, but the exact notice/copyright holder, fixture and external educational-data provenance, and permission for public redistribution need clarification from the maintainer before reuse; public visibility alone does not settle third-party data rights. The pure-function browser module appears to have no imports, whereas the full application uses Django, PostgreSQL and a REST API. The code may be bundleable without that server, but no package boundary, React build, data extraction or transitive audit was tested. GitHub metadata reports a push on 2026-10-26; recency is an observation, not a maintenance commitment.

### 3. Guitar Lab: actual practice logic but incomplete scope

**Direct evidence, high confidence:** [caged.ts](https://github.com/megomes/guitar-lab/blob/main/lib/practice/caged.ts) encodes major/minor open **chord** templates, for instance `['Dm',2,[-1,-1,0,2,3,1]]`, with low E as string index 0. It computes five chord-form regions with one fret of allowance and position-dependent playable notes; this is not a separately encoded five-position melodic-minor/harmonic-minor scale table. Its [session code](https://github.com/megomes/guitar-lab/blob/main/lib/practice/session.ts) constructs practice material and [README](https://github.com/megomes/guitar-lab) documents tab and static browser operation. The README explicitly says reference open boxes appear an octave higher in practice because practice excludes open strings. Source uses `{s,f,midi}` events; finger numbers are not intrinsic to every scale event. Verify the exact practice sequence rather than equating a chord region with a scale fingering.

**Interpretation, medium confidence:** This may serve a teacher-approved reduced major/natural-minor practice scope, not the requested jazz/harmonic minor catalogue or true low open-position exercise. Its MIT code license requires retaining copyright and permission notice; inspect the provenance of any reused separate lessons and diagrams rather than assuming every included asset is original. The [manifest](https://github.com/megomes/guitar-lab/blob/main/package.json) describes a Next/React application rather than an independently published guitar data package; any extraction, framework fit and dependencies remain untested. GitHub reports a 2026-10-10 push, not a support promise.

### 4. Scale Ninja and other apparent leads

**Direct evidence, high confidence:** [ScaleEngine.ts](https://github.com/engageintellect/scale-ninja/blob/main/app/components/ScaleEngine.ts) implements `buildCAGED` by mapping the five labels to `buildPent5` and highlighting root/third/fifth. It also defines CAGED triad voicings. Neither is evidence of five seven-note scales or either requested minor-family dataset. It identifies string 0 as low E in its triad implementation. Its [package manifest](https://github.com/engageintellect/scale-ninja/blob/main/package.json) is a Next application; extracting source and checking licensing/build behavior would be a separate task, and is not recommended for this need.

[Chromalyze](https://github.com/Jarrodth/Chromalyze) and [guitar-map](https://github.com/kwehage/guitar-map) surfaced in search, but relevant reusable CAGED shape data and rights were not established from inspected material; deprioritized rather than assumed capable. [Guitar Scale Generator](https://gamedesignerjoe.github.io/guitar-scales/) surfaced but a guessed GitHub repository URL returned 404; source/licensing could not be confirmed. These are research limitations, not definitive rejection of all capabilities.

## Minimal integration boundary, if a source is approved

Adopt the upstream licensed position/exercise data or logic itself, not a locally authored music engine. A thin adapter could retain a stable **parent tonic + family + source position identity** and return source-attributed ordered events with explicit string convention, fret, sounding pitch and optional finger. Feed the same ordered events into fretboard display and VexFlow tab/staff; use Tonal only for spelling and modal-role emphasis. Switching D melodic minor to F Lydian augmented must not regenerate or transpose the physical position. This is a proposed boundary, not evidence either candidate already implements it. Check open-string fret 0 and source transposition behavior rather than shifting an open note as a movable shape.

## Contradictions and missing evidence

- Guitar Positions' README claims MIT and five CAGED-like boxes, whereas GitHub reports no detected license and no LICENSE file; this does not prove the README's grant invalid, but its scope and notices need author confirmation. “CAGED-like” is not the same as five named canonical chord shapes.
- fretboard.js docs emphasize CAGED scale boxes and Tonal scale-name detection; source shows the actual templates are major-mode based, not separately verified for either minor family. The existence of a recognized scale does not establish a usable fingering.
- No independent proof of authorized diagram/dataset provenance, transitive license audit, tested static packaging or complete named five-position coverage across all keys/families. Automated source checks returned **unclear**, so the conclusions are based on direct source inspection rather than automated validation. No live runtime was executed.
- No teacher-reviewed range, finger assignments, open-string exceptions, ordered ascending/descending exercise, exact tablature format, or guarantee of mode-invariant identity. No evidence that the prototype fixture meets any of these requirements.

## Decisions and next steps

1. Ask a musician to review actual Guitar Positions output for major and both minor families, including D melodic minor → F Lydian augmented, one open position, an octave-shifted position, finger stretches, named-form expectations, and ascending/descending exercise boundaries. Do not label it validated CAGED before review.
2. Ask its maintainer for an explicit copyright/licensing notice covering the precise source and any included fixtures, pedagogical diagrams and third-party contributions, including public redistribution; pin an approved revision and audit dependencies before adoption.
3. In parallel, obtain teacher-provided, explicitly licensed and reviewed positions/exercises for all three families, including open variants and ordering; or agree a smaller reviewed scope and visibly mark remaining families incomplete. No custom fallback library or hand-authored shape generation is proposed.
